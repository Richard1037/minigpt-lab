# 从零写一个 GPT · 动手手册

> 新版课程入口：运行 `python webapp/pilot_server.py`，访问 http://127.0.0.1:8124/ 。主线 51 个任务、262 项测评，第三部分标量网络暂缓。公式资源可离线使用。左侧“演示完善清单”记录后续事项；继续开发前读取 [AGENTS.md](AGENTS.md)。详见 [新版课程入口](docs/新版课程入口.md)。下文保留原版课程说明。


这份手册的目标：**你亲手写出一个能生成文本的小型 GPT**，并且知道每一步为什么在那儿。
不是我写好了给你看 —— 我写的东西全部降级成"答案"，放在 `solutions/`，判据（考卷）只有一份。

面向的读者：会基本 Python 语法、没写过反向传播、不了解 transformer。
不需要 GPU，不需要 torch，全程 numpy + 标准库，CPU 上跑。

## 0. 这个项目最后会长成什么样

八个阶段，每阶段 200~600 行代码、几秒钟到几十分钟的运行时间，都有硬判据：

| 阶段 | 你要做出什么 | 动手写的文件 | 验收命令 | 就绪 |
|---|---|---|---|---|
| 1 | 标量自动微分 + 拟合直线 | `scalar.py`、`exercises.py` | `python stages/s01_fit_line.py` | ✅ |
| 2 | 非线性 MLP 拟合 sin(x) | `scalar.py`(tanh)、`exercises.py` | `python stages/s02_fit_curve.py` | ✅ |
| 3a | numpy 数组版：地基 + Scale + Linear | `nn.py` | `python tests/test_layers_a.py` | ✅ |
| 3b | 四个层（GELU / RMSNorm / Embedding / MLP） | `nn.py` | `python tests/test_layers_b.py` | ✅ |
| 3c | CrossEntropy + "gradcheck 自己可信吗" | `nn.py` | `python tests/test_layers_c.py` | ✅ |
| 4 | 因果自注意力 | `attention.py` | `python tests/test_model.py` | ✅ |
| 5 | 完整 GPT + 训练循环 | `gpt.py`、`optim.py`、`dataset.py`、`tokenizer.py` | `python stages/s05_char_lm.py` | ✅ |
| 6 | 真数据训练 + 检查点 | `checkpoint.py`（训练循环在判据脚本里，阶段 5 那个拉长） | `python stages/s06_train.py` | ✅ |
| 7 | 采样与生成质量 | `sampler.py` | `python stages/s07_generate.py` | ✅ |
| 8 | 规模升级（BPE / 更大模型） | 复用前 7 阶段的钩子 | 还没发布 | 发布中 |

**现在能开工的是阶段 1–7**：七章讲义齐全、判据可跑、测评台里都有「读讲义」。
阶段 8 还没发出 —— 发出之前它的脚本不存在，别去找 `stages/s08_*.py`。

bf16、FlashAttention 那类性能路线的存档。现在不用管它，阶段 8 之后想看再看。

## 1. 三条铁律

**铁律一：判据先于自信。**
反向传播写错**不会报错**。形状对、能跑、loss 还降 —— 三件同时成立时你的代码仍然可能是错的
（`tests/test_model.py` 里"预测自己"那条判据演示的就是这种伪装）。
所以每个阶段的验收都建立在**有限差分**上：把参数挪 1e-5 看 loss 变多少，和你手写的梯度对比。
两者对不上就是错了，没有第三种解释。判据过了，才算过了。

**铁律二：一次只改一处，改完立刻跑判据。**
七个层一起写完再测，报错信息会指向后面所有层，你会失去定位能力。
`docs/manual/s03a.html` 里给了每阶段的推荐顺序，照着走（或在测评台点「读讲义」）。

**铁律三：卡住 30 分钟以上才看答案，而且看完要关掉重写。**
答案有两个地方：`solutions/` 里那份"确实通过了全部判据"的完整实现，以及
**每份讲义里每个 TODO 末尾那个折叠的「参考答案」块**（`<details>`，默认收起，点开只出那一小段）。
折叠块只给当前这一条，不会顺带把后面几阶段的思路剧透。
抄它没有意义，但**对比它**很有意义：差异处往往是你有而判据没测出来的坏习惯，或者我有而判据没覆盖的取巧。

## 3. 怎么跑

环境：Python 3.10+（我用 3.14 验证过）、numpy 2.x。装法任选，只要 `python -c "import numpy"` 能过。

**所有命令都在项目根目录跑**（`cd D:\Transformer`）。在 `src/` 或 `src\minigpt\` 里跑会报
`ModuleNotFoundError: No module named 'minigpt'`；直接 `python src\minigpt\exercises.py`
会报 `attempted relative import with no known parent package` —— 那两个文件是包的成员，
不是入口脚本，入口是 `stages/` 和 `tests/` 下面的那些。

下面每条都是**单独一行**，PowerShell、cmd、Git Bash 里都能直接复制粘贴运行
（讲义里以前那种结尾带 `\` 的续行写法在 PowerShell 里不成立，已经全部去掉了）：

```powershell
cd D:\Transformer

# 1) 看看自己卡在哪（第一次跑一定是这个画面）
python stages/s01_fit_line.py
#   → 还没写完 → TODO-1A: 写 exercises.fit_by_autograd（见 docs/manual/s01.html#sec-7）

# 2) 写完一个 TODO 就测那一条，不用等整卷能跑（和网站按钮同一段代码）
python webapp/checks.py TODO-1
python webapp/checks.py TODO-1 TODO-2 TODO-3 TODO-1A
python webapp/checks.py            # 不带参数 = 列出全部 id

# 3) 先看看"通过"长什么样（跑答案，不跑你的代码）
$env:MGPT_ANSWER="1"
python stages/s01_fit_line.py
$env:MGPT_ANSWER=""

# 4) 全部判据一次过（阶段 5 之后才有意义，前面会跳过没写的部分）
python stages/s01_fit_line.py
python stages/s02_fit_curve.py
python tests/test_layers_a.py
python tests/test_layers_b.py
python tests/test_layers_c.py
python tests/test_model.py
python stages/s05_char_lm.py       # 完整 GPT + 训练循环
python stages/s06_train.py         # 真语料 + 检查点（读写 data/corpus.txt，存档写到临时目录）
python stages/s07_generate.py      # 采样与生成质量
```

`MGPT_ANSWER=1 python …` 那种"环境变量当命令前缀"的写法只有 bash 认；
PowerShell 里用上面 `$env:…` 那两行，cmd 里用 `set MGPT_ANSWER=1`。
Git Bash 里两种都行。

每次判据输出末尾只会有一句 `验收通过 n/N 条` 或 `验收未通过`，**通过与否只看这一行**，
不要靠"感觉 loss 在降"来判断。

## 3.5 本地测评网站（可选，但推荐）

命令行够用，但有个东西更顺手：

```bash
python webapp/server.py            # 然后打开 http://127.0.0.1:8000
```

三栏布局（三条分隔线都能拖动，双击复位）：左边阶段列表（每个阶段一条实现进度 + 通过状态），
中间是**三个视图**（「写代码」= 编辑器 + 判据结果；「读讲义」= 该阶段讲义；
「调参试验」= 把几个输入做成旋钮，跑你自己的实现），右边**提交提示**——
要交哪些文件、判据在测什么、每条判据没过最可能是什么病因、这个阶段特有的坑。

讲义和测评台是接起来的，不是两个网站：

* 讲义每节末尾有「跑 TODO-N 的单项检查」—— 结果就地显示在那一节下面，同时同步右侧槽位
  和左栏进度；「跳到编辑器」把光标放到骨架里那句占位上（已经写完的会告诉你它成了死代码）。
* 反过来，右侧 TODO 列表每条旁边有「讲义」按钮，点过去定位到讲它的那一节。
* **独立窗口**：讲义视图右上角「↗ 独立窗口」把这一章另开一屏 —— 一边读讲义一边看代码/终端，
  而不是在同一格里来回切。那个窗口**自己就能跑单项检查**（POST `/api/check`，`files` 留空 =
  跑 `src/` 里已保存的那份，所以编辑器里没提交的改动不体现在它那儿，鼠标悬停结果能看到这句）；
  它的「跳到编辑器」用 `window.open(..., 'mgpt-app')` 送回主窗口，读的位置不会被抢走。
* **章顶 TODO 小地图**：每章第一条就是这排小圆点 —— `TODO-5 ● TODO-6 ● …`，
  琥珀=还没写、灰=占位处理了但判据没跑、绿=单项过、红=单项挂，右边写「还差 N 处」。
  它是 `.chapter` 的第一个孩子且 `position:sticky`，所以钉在滚动区顶上：翻到 §9 也知道
  这章 7 处你写了 2 处；点一个点跳到讲它的那一节。状态**读的时候现取**（测评台里问宿主
  `host.progress()`，独立窗口自己拉 `/api/stages`，切回窗口还会再拉一次），不是生成时
  写死的 —— 否则刚跑完判据点还是灰的，那条带就成了误导。
* 键盘：`Ctrl+Shift+1/2/3` 切「写代码 / 读讲义 / 调参试验」，`Ctrl+Shift+R` 开结果窗口。
  （`Ctrl+1` 被浏览器占去切标签页了，抢它会按不下去，所以加 Shift。）
* 深链：`?stage=s03a&manual=1` 直接开讲义，`?stage=s02&check=TODO-4` 直接跑那条单项，
  `?stage=s02&edit=TODO-2B` 直接跳到那一行，`?stage=s02&lab=run` 打开试验台并跑一次。
  讲义单独开（`/manual/s02`）也能读和打印。
* 三栏宽度**两处都存**：先写 `localStorage` 的 `mgpt.panes`（立刻生效），再 POST `/api/panes`
  存进 `state.json` 的 `_panes`（换浏览器、换机器开同一个仓库还是那个布局）。
  `w1` 左栏、`w3` 右栏、`ch` 控制台高度；双击分隔线复位到默认值并同步回服务端。

判据结果怎么显示（这是最近改的，命令行不受影响）：

* 网站里一条判据一张卡片：左边 ✔/✘ 和色条，右边名字，下面那行是"实测 vs 阈值"。
  整块等宽文本收进卡片下面的「原始输出」里，ASCII 图和 traceback 都还在那儿 ——
  **判据本身没动**，只是不再让你在 65 行文本里找哪条红了。
* 单项快测那份「原始输出」在结果窗口（`webapp/result.html` 的 `checkCard()`）排成卡片而不是等宽文本：
  目的 = 正文（sans，公式排成衬线斜体）；输入/输出 = 名字 | 值 两列，`shape(2, 4, 5)` 做成
  `2 × 4 × 5` 的 chip、dtype 单独一个 chip、数字上色、括注压暗；判定 = PASS/FAIL 徽章。
  认不出四段的（整卷的控制台输出、BLOCKED 那一行）退回等宽文本上色。
  **用 CSS 而不是 MathJax**：这台机器连不上 CDN，公式会退回成一行 `$…$`，卡片不能赌网络。
  中间那栏的控制台仍是终端式的上色文本 —— 它是"命令行了"的镜像，四段格式在那儿照样读得出。
* 判据多时按**组**显示：组名来自脚本里的 `rep.group("…")`（比如阶段 3a 的
  「热身 · Scale：只有乘法的层，先跑绿一次」「Linear · 与逐元素手算对账（B=1, T=2, C_in=2, C_out=3）」），
  命令行用 `▸ 组名` 打头，网页用一行小标题 —— 同一个字符串，两边不会各分一套。
  没声明组的脚本（阶段 1–2）就一条标题都不加，不硬造「未分组」。
* loss 曲线画成真坐标：纵轴 log₁₀，整数十年轮标 `1e-2`，上下边界标**真实值**
  （`0.0067` 而不是 `1e-2.17`）。几条曲线共用一个坐标系，对照才看得出。
* **拟合图像**（阶段 1–2 直接看形状，比只看 MSE 有用得多）：脚本调 `rep.fit(名字, xs, ys, pred, truth=…, cx=…)`
  登记「数据点 + 真实函数 + 你的模型」三条线，网站只负责画，不另算一遍。
  散点和曲线**分开取样**：阶段 2 只有 12 个数据点，拿 12 个点连线会画成折线，看着像模型不行 ——
  所以 `cx` 给一条 200 点的密网格。数据点超过 240 个等间隔抽样，不然一次测评的 payload 要几百 KB。
* **结果窗口**：右上角「↗ 结果窗口」（或 `Ctrl+Shift+R`）把最近一次结果甩到另一屏，
  结论 / 拟合图像 / 逐条判据 / loss 曲线 / 原始输出五段，默认每 1.5s 轮询 `/api/result` ——
  这边一点「提交并测评」，那边自己就更新了，不用来回切窗口。
  它读的是 `webapp/last_run.json`（每个阶段最近一次整卷或单项），**故意不塞进 `state.json`**：
  那个文件每次刷新都要读，而判据输出动辄几十 KB。原始输出截到 60KB，截了会写明。
* 数据来自 `toolkit.Report` 的机器可读通道：网站跑时带 `MGPT_JSON=1`，脚本多吐一行
  `@@MGPT-JSON@@{…}`；命令行不带这个变量，输出一字不差。解析失败就退回纯文本 ——
  展示层永远不能把判据弄没。

调参试验台（`webapp/lab.py`，阶段 1–7 全部有旋钮）：

* 它跑的是**你提交的实现**，只是把 `n_hidden / activate / lr / decay / B·T·C·H / 温度`
  做成旋钮。**结论不算验收**：判据那几条阈值是照固定参数定的，参数一改再去比阈值就自欺欺人；
  所以它不写 `state.json`，也不改变左栏进度。
* 对照组（1 个隐藏层 + 不加激活）永远用固定参数跑，否则"比对照好多少倍"这个数没有意义。

## 4. 每个阶段的标准动作

1. 读讲义对应小节（理论部分别跳，你后面排错全靠它）。
2. 在 `src/` 里搜 `TODO-N`，看它的**契约**：输入形状、要返回什么、要缓存什么。
3. 先猜再写：拿一支笔，把形状和公式写在讲义空白处，然后才碰键盘。
   这份手册里几乎所有 bug 都属于"没想清楚就动手"。
4. 跑判据。失败时**只读第一条**错误，改一处，再跑。
   中途停在某个没写完的 TODO 时，脚本会先把**已经跑完的那几条**打出来再说下一个卡点，
   所以"写完一个 TODO 就测一次"是有效的节奏，不会什么都看不到。
5. 判据全绿后，读讲义的"这一阶段你真正确认了什么"和自查题；答不上来就回去重读。
6. 有兴趣就翻答案对比差异，然后进下一阶段。

讲义的固定结构：

```
§1 这一步在干什么         §2 必要理论（含手推例子）      §3 已给你的代码拆解
§4..§N 每个 TODO 的契约与提示                            §N+1 验收判据逐条解读
   ※ 每一节必须把**已给你的代码**也讲透（为什么这么写、不这样会怎样），
     不能只给"你要写的东西"的契约、却把给你的部分当黑盒 —— 那等于让你自己反推。
     配套的网站单项快测（ACT-* / GIV-*）测的就是这些给你的代码。
   ※ 但"讲透"要讲在**正确的阶段**：一个知识点归哪一阶段，看它是哪一步的判据需要的，
     不看它物理上写在哪个文件里（激活函数就是例子：代码在 scalar.py，知识在阶段 2）。
§N+2 常见失败模式对照表（症状 → 病因 → 修法）             §N+3 自查题
```

## 5. 术语与记号（后面所有讲义共用）

| 记号 | 含义 |
|---|---|
| `B` | batch size，一次并行处理几条序列 |
| `T` | 序列长度（token 个数） |
| `C` / `d_model` | 每个 token 的向量维度 |
| `V` / `vocab` | 词表大小 |
| `L` / `n_layer` | transformer block 层数 |
| `H` / `n_head` | 注意力头数；`head_dim = C // H` |
| `logits` | 归一化前的分数，形状 `(B, T, V)` |
| `token` | 一个最小单位，可以是字符、也可以是 BPE 子词 |
| `x.grad` | 标量 loss 对 x 的偏导（本项目里 loss 永远是标量） |
| 累加 `+=` | 所有参数梯度一律累加，清零由训练循环负责（因为多条路径会汇到同一参数） |

激活值形状约定：**`(B, T, C)`**，numpy 行主序，`float64`。
用 float64 是为了让有限差分可信；存检查点时再降到 float32。
