# Part 精修执行流程

目标：减少重复读取、临时改设计和重复验证，同时保持学习闭环、必要推导、个人数据保护及真实验收。

## 1. 一次确定范围

先以学习者身份完整走过一章，判断任务划分是否合适，再整理单题工作表。主线的单位是完整能力/真实模块；分步讲解与分项测评留在同一题、同一份代码内。主动合并割裂的操作，处理重复、前置缺口和缺失的综合收尾；不要先把既有碎片逐题完善，再等待用户指出划分本身不合理。代码/公式/页面通过不能代替这层审查。2026-11-16注意力八个台阶的教训：清单完成不等于课程好学。

读取衔接记录的当前结论、该Part清单和适用的全局要求，按需查历史证据；不反复整篇输出长文档。将本Part任务汇总成一张工作表：已有能力、本次增量、复用文件、后续用途、讲解缺口、展示难点、验收条件。

先检查章末是否综合前面内容、是否要求重复实现、是否使用尚未学过的概念。已有明确授权和偏好直接沿用，常规实现选择自主处理；确实需要用户决定的重大教学取舍尽早提出。

## 2. 提前发现接线风险

开始写正文前，一次确认持久生成入口、任务契约、网页执行、本地导入、骨架同步、成绩版本和展示入口。重点区分同域执行与分模块import。保留基线快照，只处理本轮相关的共享机制问题；无关重构登记后续。

已有功能和测试工具优先复用，不为每个Part另建一套近似工具。不把整理整个工程作为精修每部分的前置。

## 3. 集中实现

先确定各题讲解顺序、接口、必要推导、样例和展示形式，再集中完成持久教学源、骨架、增量测评与展示接线。每题只增加新的学习能力，复用已有个人实现。

展示先明确解决的理解难点。逐元素函数、行内统计、共享参数和模块组合分别选择适合的形式；无需交互的内容使用清晰公式或静态关系图。复用已有UI组件，避免做完通用矩阵动画才重新判断是否适合。

## 4. 分层验证，按变更重跑

- 修改算法、测评或导入链后，运行对应数值、状态及错误实现拒绝检查。
- 修改正文/数学排版后，检查公式、符号与代码标识；不因此反复运行无关模型测试。
- 实现稳定后，统一运行一次本Part专项、生成一致性和受影响的共享回归。相互独立的检查并行调用，输出失败摘要。
- 网页接口与本地导入至少各验证一次；浏览器集中检查所有本轮页面的排版、真实交互与折叠，保存代表截图。只使用获准的侧边栏预览。
- 失败或新改动只重跑相关检查；改到共享机制时才增加受影响回归。修复后最终必要检查通过，停止无依据的重复验证。

不减少必要推导、高维输入、错误实现拒绝、真实个人模块复用、数据保护和用户验收。测试通过只标review。

## 5. 集中收尾

统一比对课程范围与个人文件快照，核对备份，最后同步清单、能力覆盖、事实快照和衔接记录。其他Part和已验收状态保持。最终只报告完成范围、必要检查、数据迁移和下一批待办。

中途进度说明聚焦新发现及下一步，避免重复复述计划或把已经通过的检查再次当作新进展。后续若仍有明显耗时，优先定位设计返工、接线问题或重复验证的来源，再改善流程。
