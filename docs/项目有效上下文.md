## 产品目标与课程蓝图

在本地中文网站内，通过阶梯式学习，亲手完成 Python + NumPy 的可训练 decoder-only miniGPT，支持训练、续训、生成和保存恢复。核心前后向由学习者实现，不依赖 PyTorch/自动求导代写；网站提供讲解、必要展示、编辑与评测。

| Part | 目标与边界 |
|---|---|
| 01 整体架构 | 认识输入、层、参数、损失与训练闭环 |
| 02 NumPy 与张量 | 索引、轴、归约、广播、变形、矩阵运算及对应反向所需能力 |
| 03 标量网络 | 继续暂缓；未来可作按需补基础的选修，不强制已有基础的学习者重做 |
| 04 完整基础层 | Parameter/Module、初始化、Scale、唯一 Linear、Embedding、GELU、RMSNorm、MLP；末节真实组合 MLPBranch 并分路径验收基础组件 |
| 05 概率与损失 | 稳定 Softmax、交叉熵，全位置平均与完整梯度 |
| 06 注意力与 Transformer | 三个完整任务：AttentionCore→MultiHeadAttention→Block；步骤在各页内部讲解和分项检查；六个小练习与Dropout/LayerNorm为选修 |
| 07 GPT 组装 | 词表与位置嵌入、Block 堆叠、最终归一化、共享输出权重；此时讲 GPT 初始化配置和残差出口缩放 |
| 08 优化与训练 | 数据窗口、优化器、梯度管理、训练与验证，真实调用个人模块 |
| 09 生成与保存 | 采样、上下文窗口、检查点接口。端到端交付进入训练实验室 |

主线采用 Pre-Norm RMSNorm、GELU、可学习 token/位置表、因果自注意力及 token/输出权重共享。原始 Transformer、LayerNorm、Dropout、排错、数值误差与有限差分归拓展或结构对照，不能混成主线新增依赖。真实文件/接口以当前源码为准。

## 每题必须形成的学习闭环

- 先像回答“我是小白，怎样理解这个板块在做什么”一样，讲清对象、输入、过程、输出。先解释已有代码和本次新增能力，再让人动手。
- 先讲整个函数的语义功能、输出信息及后续用途，再讲操作；明确核心与外层职责。AttentionCore负责Q/K/V到读回内容，多头外层负责X到最终Y；多头允许同位置多份读取比例，各头投影参数不同但由同一预测损失联合训练，举例不代表固定职责或必然差异。
- 制作顺序是完整讲解底稿→题目与页面→工程检查。每节从刚学完上一节的视角通读：能否解释新增能力、每步目的与连接、参数/缓存归属和反向用途；用贯穿例子补连接。不能只给操作名/形状清单，不能仅在首节加整体说明后默认相邻节也已讲清。测试、排版和清单完成不能替代理解检查。
- 自然语言简洁，不删理解必要的步骤和例子；不写教学规划思路、范围免责声明、“不做什么”等冗余内容。用户已认可的讲解保留内容和顺序，只改善排版。
- 必要公式紧邻计算：先定义符号和前向，再解释局部导数、上游、反向来源、求和/广播轴与缓存。完整必要推导保留；更深原因、误差分析放拓展。
- 每段反向推导旁重新列出对应原始前向函数，随后区分上游与局部导数，避免回翻查找。用户指定数学与图示梯度统一为∇X，表示∂L/∂X、与X同形；不用dX作为公式记号，实际代码变量名保留。
- 随后一道 OI 风格实现题：实现接口、题目描述、输入格式、输出格式、状态变化、样例解释与 miniGPT 用途。
- 题面末尾、样例/编辑器之前集中列“动手任务清单”“关键公式速查”，写清需实现的方法、缓存、返回、梯度累计与归约轴。
- “先学明白”末尾、题目之前另有“核心总结”：整体公式＋一句作用＋少量步骤对应，把分步内容收回整体；标清必要符号和本项目实际掩码/偏置/归一化/残差约定。此处用于概念收束，题末清单用于实现核对，不相互替代，也不重复整套推导。
- 变量必须先交代来源再使用：区分调用方输入、构造时选定配置、持久可训练参数、前向中间结果与反向上游。数学名字与实际对象/返回值对应清楚，不能先抛整网公式再在不同折叠区补定义。用同一个输入例子贯穿步骤，但仍按“整体用途→准备与来源→前向主线→实现准备→核心总结”的层级组织，避免把聊天式解释拆成散点。组合课复用已学组件的反向，只交代调用顺序和新增的接线/共享/归约动作；必要公式留在实现核对，最终总结以完整前向流程图、整体公式和一句功能解释收束。
- 每题是 miniGPT 的真实组件或学习必需的知识应用题。检查“之前已会什么、本次新增什么、复用哪个个人实现、后续实际用在哪”。
- 先审结构，再完善单题：完整走一遍学习过程，主动判断能否建立整体认识，排查碎片化/重复/前置缺口。讲解步骤放在完整任务内部，同一份代码逐步完成；主线按完整能力划分，细粒度测试留作分项检查。不要把每个公式拆成必修小题，或为一行计算强制建立跨文件helper。八个碎片逐题修好仍会割裂整体，数值/公式/UI通过不能作为教学结构已合理的证据。
- 以一份个人核心实现增量完善；章末组合前面成果，尽量少做重复工作。不能复制同一类清空方法再称必修进阶，也不能为了凑齐组件虚构网络或提前使用未学对象。
- 实现与评测必须留给学习者；把完整函数藏在参考答案中不能替代实现任务。旧用例通过/参考实现存在，不证明个人代码已完成或最终模型已复用。
- 所有项目计算模块和组合包装均由学习者实现。助手仅提供讲解/接口/TODO/测评/折叠参考，不能填好包装后作为下游依赖，不能在普通运行中注入参考替代未完成先修。文件来源、当前测评状态与亲手实现/理解分开判断。

## 排版与交互偏好

- 公式、向量、矩阵、形状、上下标和数学关系用 LaTeX/KaTeX。小矩阵紧凑带括号；不要用铺满页面的数字表或纯文本拼公式。必要自然语言仍保留。
- 类、属性、函数调用用行内代码；检查实际正文节点，不能只以公式解析无错误作为排版完成。
- 完整示例/参考代码默认折叠，Python 高亮同编辑器。一个可编辑代码框，支持括号补全、缩进和按缩进级退格；仅未在上文解释的给定代码补注释。
- 样例输入输出与演示可折叠；测评每项紧凑单行、详情展开、失败定位清晰，不重复显示两份结果。
- 正文单列；顶部合并工具栏与目录按钮，展开树状面板选题后收起；全局清单/模型地图/通用拓展只有顶部统一入口，独立面板打开。
- 训练语料和训练参数使用全站常驻的可折叠实验设置栏，与正文独立滚动。收起时保留展开入口，切换课程保留状态。更改设置即时保存，对下一次训练生效，已开始的训练沿用提交时的配置。
- 模块内多任务使用紧凑列表，序号、标题、测评、讲解状态对齐；当前任务浅绿突出。模块概览与列表合为一个容器，避免弹性卡片的宽窄不一和末行拉伸；窄屏把状态移到标题下方。
- 页面大小保持不变，仅编辑框可调整尺寸。目录章行背景表示整章进度；进度与讲解验收分开。
- 区分计算主线（前向/反向）、实现准备（构造/缓存）与较轻的设计补充，避免不同重要性并列大卡片。前置任务跳转提供明确返回入口、浏览器后退/前进，并恢复原滚动及折叠状态。
- 读取本地代码直接覆盖编辑器显示，无额外确认；浏览器草稿优先，无草稿读实时 local_code。保存/恢复流程仍须保护个人文件。

## 可视化决策与反例

制作前先问：具体解决哪个理解难点？默认整体能否看懂？源对象、动作、去向是否可见？直接/间接/无关区域是否准确？保留全部 batch/head/token 了吗？统计轴和共享轴区分了吗？公式/曲线/模块关系会不会比大表更清楚？

- 默认展示整个运算及完整张量，先讲各位置共同规律、归约与共享；单格数值仅作默认收起的核对。不能把第一维设 1 隐去高维，也不能把六个微观例子拼成宏观讲解。
- 最新补充：先讲模块的整体意图与步骤用途，至少建立直观认识，深层原理可放拓展；认可的聊天解释完整整合。独立batch/head若规则重复，默认一个可切换代表切片，标明完整形状，其余按需切换；不改真实维度。跨位置/共享参数汇总仍显示必要全部来源。正文和每个反向交互视图都要就地列对应前向函数，不能只在正文补一次。
- 矩阵层：同时摆出相关矩阵，点格子高亮前向影响/反向来源；用各位置外积之和解释共享权重梯度。形状相合、矩阵乘法算法、单个数字来源都不能代替求导来源。
- Embedding 已获肯定：编号、全部 batch 的上游、词表梯度并列；选行、回行、重复编号累加明确。数值可换成可区分的符号/颜色。
- GELU：曲线、局部切线、两条导数路径；用户明确否定七张同形点阵同格高亮。
- 归一化：行内特征统计与跨位置参数求和分别讲。避免十二张重复大表淹没关系。
- 交叉熵：完整源概率/对数概率矩阵、标签选中格、取出/取负结果与平均去向。重复坐标公式表不是来源图，已被用户否定。
- 多头布局已否定密集下标与三张重复中间表。用明确token/头标签的片段说明分组变化，只保留前后对应；一批次可切换，Q/K/V同类拆头只举Q。完整流程每步变量须连续，投影→分割→拆轴→换轴→读取→换轴→合轴→输出投影，反向就地逐步对应，不跳过连接操作。
- 组合：持久子层与返回值传递；残差：前向分叉、反向合流。不要强加移动圆点、装饰动画、播放按钮；一句话能清楚说明时不做占空间交互。
- 用户指出当前展示问题，先实际修正并检查，再记清单；不能只登记。保留确有帮助且已认可的过程交互，因运算选择形式。
