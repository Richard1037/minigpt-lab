## 每页统一标准

1. 开头用一句话明确交付：实现哪个函数或哪些方法，本节是否包含反向。概念题明确只需判断，不写代码。
2. 为每个输入、构造条件、输出、中间变量说明名字、含义、形状/类型。固定 axis、keepdims、排列顺序也显式列出。
3. 样例沿同一个输入展示来源→操作→中间结果→输出，不只给两张终态表。不用具体数值乘加掩盖位置与路径。
4. 步骤必须是可执行动作，不能重复目标充数。前向、缓存、反向返回值、参数梯度副作用分别写明。
5. 推导紧接对应计算。前向练习不要突然要求未定义的反向；完整层保留完整必要推导，不能以简洁为由删去。
6. 修改课程的生成源，保证重建仍生效。保留个人练习、草稿和成绩；改变接口/标准时明确迁移并使旧成绩失效。

## 第二轮：学习闭环与验收审查

用户进一步要求不只修文字，要从学习者视角检查全站的不合理处。以下已通过读取实际骨架、依赖和测评器核对；仍是待实施项，不代表已修复。

### 已确认的功能或表述缺陷

1. **形状练习的通过标记不能证明其全部要求。** `shape` 要求先转 float64，返回一维整数形状；实际 `_checks.evaluate` 只比数值/形状，不查返回 dtype。实测 `lambda values: np.array(values.shape,dtype=np.float64)` 不做所要求的转换，返回浮点形状，仍 4/4 通过。返回形状的接口本身也无法观察内部是否完成 dtype 转换。修订应将不可观察的内部要求改为演示，或明确返回可验证的产物；不得靠静态搜索代码字符串冒充正确性检查。
2. **个人公共接口练习与最终模型脱节。** `infrastructure` 不在任何后续模块 dependencies 中；网页 RUNNER 注入 `foundation_core` 的 Parameter/Module/initialize，个人本地骨架也从这里导入。它不是学习者公共接口的实际复用。应统一接通个人实现和相应类型检查，或在课程中诚实限定练习性质；不能宣称最终项目完全复用该题个人实现。变更会影响 runner/probe/isinstance/本地导入，须由主线程整体处理，不能只增加一个依赖名。
3. **通用测评标签误导。** arrays 多题统一标“零值/不同轴长/重复编号”，即便随机数或 reshape 不涉及重复编号；GELU/Softmax 等无参数层仍标“全部参数梯度”，Embedding 的零上游说明误称输入梯度。应根据实际用例与层类型生成准确标签。
4. **概念检查冒充实现目标。** initialization 的目标写“初始化权重”，只有两道选择题，无手写初始化任务，且基础 initialize 直接提供。可保留概念题，但必须明确本页只判断；若初始化是必需实现能力，就补实际构造任务，并说明 GPT 的 0.02 初始化和基础 fan-in 初始化适用范围。
5. **模板覆盖层的特殊语义。** Embedding backward 返回 None、GELU 无参数，与通用 goal/steps 直接矛盾；独立 GPT 的构造器状态也矛盾。优先修复，不能单靠换更漂亮的公式。

### 讲解→练习→验收的覆盖缺口

| 区域 | 当前问题 | 应如何闭环 |
|---|---|---|
| reduce / broadcast | 讲归约、广播及两类反向，仅练去均值/加偏置前向；直接跳完整 Linear 反向。 | 在同模块加入均值反向、广播参数归约、去均值双路合流的普通实现练习；固定上游 G 明确定义。不能把可选 fix_bias 当必修教学替代。 |
| reshape / transpose / heads | 讲恢复和逆置换，只练单向；逆操作在 Linear/MHA 综合题中才突然出现。 | 合并/恢复及换轴/逆换轴成对小步骤；合头 att_merge 已有，但应连接来源与逆向练习，避免重复造同题。 |
| copy | 讲视图/缓存生命周期，练习只要求复制并改一格。 | 加共享内存/缓存被修改的预测与验证，或明确后续层对缓存的行为验收位置；不能据此声称已掌握缓存。 |
| random / initialization | 讲随机状态推进和缩放时机，只练固定 seed 新生成器采样。 | 加连续调用状态的判断/验证，以及初始化的明确可测产物；GPT 构造再综合验收。 |
| Parameter/Module | 一题同时递归、容器、去重、缓存过滤、清零，没有分步指导。 | 在同一模块分小交付；清楚标出先完成容器，再递归收集，再共享去重，再 zero_grad。 |
| Linear/Embedding/Norm/MLP | 完整前反向有真实测评，不应误称没有练习；但粒度与依赖说明不清。 | 保留完整验收，先给前向/缓存/输入梯度/参数梯度阶段反馈，再组合；明确前置数组操作映射。 |
| 注意力 | 有四个前向分步练习、完整三路反向测评，但中间反向来源缺少独立脚手架。 | 增加 dV/dA→Softmax→dQ/dK 的来源和步骤检查，最终仍必须自己实现完整 core，不能止于小题。 |
| GPT/权重共享 | 完整模型确实测共享梯度，但从 Embedding 到双路径共享表跃迁较大。 | 先区分查表路径和输出头路径，再合并参数梯度；可选 fix_shared 不能代替正常主线构建。 |
| 优化器/训练/检查点 | 并非没有练习，实际含状态测评；但单题捆绑多项且步骤只是重复目标。 | 裁剪→单步 AdamW→状态连续更新；单步训练→多步；保存→恢复→续训对照，按子交付反馈。 |

### 学习者路径的不合理处

- 第二部分 reduce 在 broadcast 之前就使用广播，且提前讲反向。应先补即时所需的广播解释或调整顺序，再引入反向任务；不要要求学习者猜未讲概念。
- 第一至九部分“已开放”和“全部掌握”是不同含义。通过数量不能证明独立编写、过程理解或尚未覆盖的能力；主线完成页应准确说明验收范围。
- 不应为了补覆盖将所有概念拆成侧栏独立章。一个模块内安排多个递进任务，概念识别、短实现、完整模块与迁移验证各自定位。
- 不应把每条公式都机械新增一个题。已有后续完整层实际验证的能力应明确链接，真正缺失的基础操作才增加练习。
- 对每项必修能力建立映射：首次解释位置、演示位置、动手任务、真实测评项、最终组合使用位置。没有实现/验收映射的内容不能标记“已掌握”。
